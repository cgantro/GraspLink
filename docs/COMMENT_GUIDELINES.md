# 코드 주석 작성 기준

대상 독자: C++ 초급~중급 개발자. 그래픽스·로봇·물리 지식이 없어도 코드 흐름을 따라갈 수 있게 쓴다.
설명 본문은 한글로 작성한다. Doxygen 태그, 코드 식별자, API 이름과 단위 표기는 원래 표기를 유지한다.

## 문장 길이

- 주석은 짧은 구절과 항목을 우선한다. 완전한 문장은 꼭 필요한 설명에만 쓴다.
- `역할:`, `입력:`, `출력:`, `좌표:`, `단위:`, `흐름:`, `이유:` 같은 표기를 활용한다.
- 용어만 나열하지 않는다. 낯선 용어는 코드에서 하는 일을 짧게 덧붙인다.
- 명사형 문서체, 영어 직역, 코드 내용을 그대로 읽는 주석은 피한다.
- 코드 한 줄마다 주석을 붙이지 않는다. 이유·데이터 방향·좌표·단위·수명처럼 코드만으로 놓치기 쉬운 내용만 적는다.

## 설명할 내용

- 참조 객체의 소유자와 파괴 순서
- 위치·회전·크기의 단위와 Local/World 기준
- Fixed Update에서 값이 움직이는 순서
- Dynamic/Kinematic/Static 물체를 누가 움직이는지
- Collider 크기와 중심의 기준
- 현재 지원하지 않는 기능과 영향

기본 C++ 문법과 일반 STL 사용법은 설명하지 않는다. 같은 개념을 여러 파일에서 반복하지 않는다.

## 타입과 함수

- 타입: 맡은 역할과 다른 모듈의 책임
- 함수: 바꾸는 값, 주요 입력의 단위·좌표, 결과와 제한
- 중요한 계산: 수식보다 계산 이유와 값의 방향
- 타입과 공개 API는 Doxygen 형식으로 작성한다. `@brief`로 역할을 요약하고 `@details`로 배경지식·설계 이유·좌표계·데이터 흐름을 설명한다.
- `@param`, `@return`, `@throws`는 입력·출력 계약을 이해하는 데 필요할 때 사용한다. 미구현 기능은 실제 코드에서 확인한 경우에만 `@todo`로 적는다.
- 중요한 계산과 GPU/물리 상태 전환은 구현 위치에 일반 `//` 주석을 덧붙인다.
- 짧게 요약하는 과정에서 필요한 배경 설명을 삭제하지 않는다. Render Pass, Shadow Pass, FK, COM처럼 낯선 개념은 해당 코드에서 어떻게 쓰이는지 풀어 설명한다.

## 예시

```cpp
/**
 * @brief 선택된 Mesh를 GPU에 그리고 프레임의 렌더링 단계를 관리한다.
 * @details
 * RenderSystem이 그릴 대상을 선택하고 Renderer는 OpenGL 상태와 draw 명령을 처리한다.
 * Shadow Pass는 광원에서 본 깊이를 저장하고, Main Pass는 그 깊이로 그림자를 판단해 화면 색을 만든다.
 * MSAA는 픽셀마다 여러 표본을 저장해 경계를 부드럽게 한다. 프레임 끝의 resolve는 이 표본을
 * Window 기본 framebuffer로 합치는 단계다. 소유한 GPU 자원을 해제할 때까지 GL context가 살아 있어야 한다.
 */
```
