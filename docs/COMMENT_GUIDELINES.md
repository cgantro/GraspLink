# 코드 주석 작성 기준

대상 독자는 C++ 문법과 기본 STL은 알지만 그래픽스·로봇·물리 분야의 배경지식은 없는 개발자다. 설명은 한글 완전한 문장으로 쓰고, Doxygen 태그와 실제 코드 식별자, API 이름, 단위 표기는 원래 표기를 유지한다.

## 낯선 개념을 설명하는 순서

- 분야 용어는 독자가 처음 접한다고 가정한다. 용어의 뜻을 먼저 설명하고, 그다음 이 코드가 그 개념을 어디에 쓰는지 설명한다.
- 비슷해 보이는 개념은 첫 등장 때 차이를 함께 밝힌다. 예를 들어 Local은 바로 위 부모를 기준으로 한 값이고 World는 Scene 전체 기준 값이다. CollisionLayer는 어떤 종류의 물체와 부딪힐지 정하고, BodyMotionType은 누가 그 물체를 움직이는지 정한다.
- 필요한 경우 현재 프로젝트의 바닥, 로봇 팔, 그리퍼, 상자 같은 구체적인 사례를 쓴다. 용어를 한국어로 바꾸거나 설명 없이 나열하는 것으로 배경 설명을 대신하지 않는다.
- Entity는 장면 안의 물체를 가리키고, Component는 위치나 회전처럼 그 물체에 붙는 값이라는 점을 설명한다. Entity 클래스가 실제 장면 물체를 소유하는지, ID나 handle만 보관하는지, 실제 수명 관리자가 누구인지 구별한다.
- Flecs query, binding, observer, cache, tag, snapshot 같은 말은 첫 사용에서 일반 C++ 독자가 이해할 뜻과 이 코드의 역할을 함께 설명한다. 이후에는 같은 문서 흐름에서 이미 정의한 용어를 짧게 다시 쓸 수 있다.
- Forward Kinematics(FK)는 관절 각도에서 각 로봇 링크와 도구 끝의 위치와 방향을 계산하는 과정으로 설명한다. collision proxy는 화면에 보이는 상세 모델과 별개로 충돌 계산에 쓰이며 화면 모델을 따라가는 단순 물체라고 설명한다.
- 화면 좌표를 잠시 재사용하는 overlay cache는 저장 대상과 갱신 주기를 설명한다. 예를 들어 100 ms 동안 화면 선 좌표를 재사용하면 카메라 이동 직후 선이 잠시 이전 투영 결과에 남을 수 있다. 카메라 뒤의 점을 건너뛴다면 원근 투영에서 앞에 있는 물체처럼 잘못 나타나는 것을 막기 때문이라고 설명한다.

## 문장과 형식

- 짧게 요약하면서 독자에게 필요한 뜻, 데이터의 출처와 사용처, 조건, 수명, 단위 또는 좌표 기준을 빼지 않는다.
- `역할:`, `입력:`, `출력:` 같은 표지와 명사 나열을 기본 형식으로 쓰지 않는다. 코드의 목적과 동작을 자연스러운 문장으로 연결한다.
- C++ 식별자와 API 이름은 실제 이름 그대로 유지한다. 의미를 더해 보이려고 코드에 없는 새 이름을 만들거나 구체적인 객체를 추상적인 장치로 바꾸지 않는다.
- 문장은 끝난 뒤에만 줄을 바꾼다. 고정 열 너비에 맞추려고 문장 중간을 자르거나, `@details` 다음 줄을 정렬하려고 추가 들여쓰지 않는다. 생각이 바뀌는 곳에는 빈 주석 줄로 문단을 나눈다.
- 기존 코드의 동작, 지원 범위, 좌표계, 단위, 수명과 제한을 주석에 그대로 반영한다. 코드에서 확인하지 않은 기능이나 의도를 주장하지 않는다.
- 코드 한 줄마다 주석을 붙이지 않는다. 코드만으로 알기 어려운 도메인 배경, 데이터 흐름, 상태 변화와 제약을 설명한다.

## 타입과 함수

- 타입 주석 하나만 읽어도 이 타입이 무엇을 위한 것인지, 자료가 어디서 와서 어디에 쓰이는지 이해할 수 있게 쓴다.
- 공개 타입과 API는 Doxygen 형식을 사용한다. `@brief`에는 기능을 쓰고 `@details`에는 필요한 분야 배경, 이 코드의 사용 방식과 제약을 설명한다. 태그 본문도 위 문장 규칙을 따른다.
- `@param`, `@return`, `@throws`는 호출 계약을 이해하는 데 필요한 경우 사용한다. 매개변수 설명도 값의 의미, 단위 또는 좌표 기준을 빠뜨리지 않는다.
- 중요한 계산과 GPU 또는 물리 상태 변경은 구현 위치에서 일반 `//` 문장으로 설명한다.
- 주석은 기본 C++ 문법이나 코드 자체를 다시 읽지 않는다. 대신 계산 이유, 데이터 방향, 소유권과 파괴 순서, 위치·회전·크기의 기준과 단위, Fixed Update의 실행 순서, 물체를 움직이는 주체, Collider 크기와 중심의 기준, 현재 지원하지 않는 기능과 그 영향을 설명한다.

## 예시

```cpp
/**
 * @brief 충돌 검사에서 물체 종류를 나누는 CollisionLayer를 정의한다.
 * @details CollisionLayer는 물체가 움직이는 방식을 정하지 않고, 어떤 종류의 물체와 부딪힐 수 있는지를 정한다.
 * 예를 들어 로봇 팔이 상자와 부딪혀야 한다면 Robot과 DynamicObject의 조합을 허용해야 한다.
 * 바닥은 Environment로 분류할 수 있다. Static, Kinematic, Dynamic은 움직임을 누가 정하는지 나타내는 BodyMotionType의 값이다.
 * 바닥은 Static이라 움직이지 않고, 로봇 팔은 Kinematic이라 로봇 코드가 목표 자세를 정하며, 상자는 Dynamic이라 중력과 충돌 결과에 따라 움직인다.
 */
enum class CollisionLayer;
```

```cpp
/**
 * @brief 물리 계산에서 누가 물체의 움직임을 정하는지 나타낸다.
 * @details BodyMotionType은 어떤 종류의 물체와 부딪힐지 정하는 CollisionLayer와 다른 설정이다.
 * 바닥이나 벽은 Static이라 움직이지 않는다. 로봇 팔은 Kinematic이라 로봇 코드가 매번 목표 자세를 정한다.
 * 상자는 Dynamic이라 Jolt가 계산하는 중력과 다른 물체와의 충돌 결과에 따라 움직인다.
 */
enum class BodyMotionType;
```
